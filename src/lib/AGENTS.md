## Copilot feature rules (src/lib)
- Risk check logic lives in `src/lib/copilot-risk.ts`: amounts, dates, identity and late-fee/deposit rules are pure code, the model only proposes language flags, and every model quote must match the draft exactly once or it is dropped and counted — so the model output shape is never trusted. Results are stored only in `copilot_drafts.risk_flags` (with `checked_body`), never in new tables, with a top-level `status`: `complete`, or `partial` when the language review failed (rule-check results kept, semantic layer `not_run`); results without `status` predate it and were complete. The UI (`RiskResults` in `src/components/risk-check.tsx`) branches only on that status so a partial can never render as a pass, and `decideDraft` refuses to approve a partial without `partial_review_acknowledged`, auditing it as `approved_after_partial_review`.
- Photo triage (`src/lib/copilot-triage.functions.ts`): photos live in the private `maintenance-photos` bucket and are only shown or sent to models via short-lived signed links. Concept choice, the five-field answer schema, and the hard rules (no cause/health/cost in findings, no cost in drafts, no findings → code-written clearer-photo request) are pure code in `src/lib/copilot-triage.ts`; SAM text parsing and the per-concept stage are in `src/lib/copilot-segmentation.ts`: an empty output lane is zero regions for that concept (not an error), while HTTP errors, missing settings and malformed non-empty replies still fail as model_error. The tenant reply is a normal `copilot_drafts` row (maintenance_update) so it reuses risk check and approval; the work order lives in `copilot_photo_triage.findings`.
- Tenant Q&A (slice 4) is self-contained so it can be deleted cleanly: `src/lib/copilot-qa.ts` (pure scope check, topic detection, single-fact answers, not-in-the-record rule, figure verification), `src/lib/copilot-qa.functions.ts` (`askAboutTenant`, reads only the page tenant's row plus every demo tenant's name and property label — nothing else, for the case-insensitive scope check, never sent to the model — and writes only `qa`/`model_error` audit rows), `src/components/tenant-qa-panel.tsx` (one line on the tenant page). Other slices must not import from it. Audit rows may carry `detail.summary`, which the audit list shows as is, so self-contained features need no audit code elsewhere.
- Compose-flow draft language (English/Spanish, `DRAFT_LANGUAGES` in `src/lib/copilot-shared.ts`) is stored only in the draft's `generate` audit row `detail.language` (copilot_drafts has no language column, by choice — no migration); `getDraft`/`decideDraft` read it from there and drafts without one are English. Spanish changes only the prompt instruction, never the facts, and the risk check runs on the text unchanged.
- Audit log page: `listAudit` returns each row's one-line summary plus its full stored `detail`; plain-language labels live in `src/lib/copilot-audit.ts` (pure), and the expanded row always also renders the full stored record so a newly recorded field is never hidden.
